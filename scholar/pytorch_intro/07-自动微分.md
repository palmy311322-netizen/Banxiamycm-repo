# 自动微分

> 本章目标：理解 `torch.autograd` 如何记录计算图、计算梯度，掌握 `requires_grad`、`backward()`、梯度累积、`no_grad()` 和 `detach()` 的使用场景。

官方教程：[Automatic Differentiation with torch.autograd](https://pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html) · [Autograd Mechanics](https://pytorch.org/docs/stable/notes/autograd.html)

## 1. 为什么需要自动微分

训练神经网络的核心是**反向传播**：

1. 前向计算得到预测；
2. 用损失函数衡量预测与标签的差距；
3. 计算损失对每个参数的偏导数（梯度）；
4. 沿梯度反方向更新参数，使损失变小。

手写导数既繁琐又容易出错。`torch.autograd` 会在前向计算时记录运算，并在调用 `backward()` 时自动用链式法则求出所有梯度。

## 2. 一个最小例子

```python
import torch

x = torch.ones(5)                  # 输入
y = torch.zeros(3)                 # 期望输出

w = torch.randn(5, 3, requires_grad=True)   # 权重参数
b = torch.randn(3, requires_grad=True)      # 偏置参数

z = x @ w + b
loss = torch.nn.functional.binary_cross_entropy_with_logits(z, y)
```

这里：

- `w`、`b` 是**叶子张量**，且 `requires_grad=True`，需要计算梯度；
- `z`、`loss` 是由运算产生的新张量，不是叶子。

## 3. 计算图与 `grad_fn`

前向计算时，autograd 会构建一张有向无环图（DAG）：

```text
x ─┐
   ├─ matmul ─ z ─┐
w ─┘             ├─ add ─ ... ─ BCEWithLogits ─ loss
b ───────────────┘
```

每个由运算产生的张量都带有 `grad_fn`，指向创建它的反向函数：

```python
print(z.grad_fn)      # <AddBackward0 object at ...>
print(loss.grad_fn)   # <BinaryCrossEntropyWithLogitsBackward0 object at ...>
```

- 叶子张量（由用户直接创建）通常 `grad_fn is None`；
- 非叶子张量的 `grad_fn` 记录了它是如何被计算出来的。

## 4. 计算梯度

```python
loss.backward()

print(w.grad)
print(b.grad)
```

`loss.backward()` 会：

1. 从 `loss` 出发，沿计算图反向遍历；
2. 对每个 `grad_fn` 计算局部导数；
3. 用链式法则把梯度传播到叶子张量；
4. 把结果**累加**到叶子张量的 `.grad` 属性。

### 4.1 只有叶子张量默认有 `.grad`

```python
print(z.grad)   # None（z 不是叶子）
print(loss.grad)  # None
```

如果需要非叶子张量的梯度：

```python
z.retain_grad()
loss.backward()
print(z.grad)
```

### 4.2 对标量输出才能直接 `backward()`

当输出是标量（如损失）时：

```python
loss.backward()          # 等价于 loss.backward(torch.tensor(1.0))
```

当输出是任意张量时，需要传入与输出同形状的梯度向量 `v`，计算的是 **Jacobian 向量积** `vᵀJ`，而不是完整 Jacobian 矩阵：

```python
out = (inp + 1).pow(2).t()
out.backward(torch.ones_like(out), retain_graph=True)
```

## 5. 梯度会累积

这是初学者最容易踩的坑。默认情况下，梯度是**累加**的：

```python
loss.backward()
print(w.grad)       # 第一次的梯度

# 如果没有清零，再做一次 backward：
loss.backward()     # 报错：图已经被释放
```

即使使用 `retain_graph=True` 允许重复反向，梯度也会叠加：

```python
out.backward(torch.ones_like(out), retain_graph=True)
print(inp.grad)                     # 第一次结果

out.backward(torch.ones_like(out), retain_graph=True)
print(inp.grad)                     # 变成第一次的 2 倍

inp.grad.zero_()                    # 清零后重新计算
out.backward(torch.ones_like(out), retain_graph=True)
print(inp.grad)                     # 恢复为第一次结果
```

因此训练循环中必须清零梯度：

```python
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

> 默认 `optimizer.zero_grad(set_to_none=True)`，会把 `.grad` 设为 `None` 而不是填 0，更省内存。

## 6. 关闭梯度跟踪

推理或冻结参数时，不需要构建计算图。

### 6.1 `torch.no_grad()`

```python
z = x @ w + b
print(z.requires_grad)      # True

with torch.no_grad():
    z = x @ w + b
print(z.requires_grad)      # False
```

适合：

- 模型评估 / 推理；
- 不需要梯度的前向计算；
- 冻结部分参数后仍要执行前向。

### 6.2 `detach()`

从计算图中分离出一个共享底层数据、但不带梯度历史的新张量：

```python
z = x @ w + b
z_det = z.detach()

print(z_det.requires_grad)  # False
print(z_det.data_ptr() == z.data_ptr())  # True，共享存储
```

常见用途：

- 把张量转成 NumPy / 记录日志；
- 阻止梯度流经某条分支（如目标网络、经验回放）。

### 6.3 `requires_grad_(False)` 冻结参数

```python
for param in model.parameters():
    param.requires_grad = False

# 只训练最后一层
for param in model.fc.parameters():
    param.requires_grad = True
```

冻结后优化器仍会遍历所有参数，但只有 `requires_grad=True` 的参数会收到梯度。更严谨的写法：

```python
optimizer = torch.optim.SGD(
    filter(lambda p: p.requires_grad, model.parameters()),
    lr=1e-3,
)
```

### 6.4 `torch.inference_mode()`

比 `no_grad()` 更彻底的推理模式，会额外关闭版本计数等机制，速度更快：

```python
with torch.inference_mode():
    pred = model(X)
```

只用于推理，不要用于训练。

## 7. 动态计算图

PyTorch 的计算图是**动态**的：

- 每次前向传播都会重新构建一张图；
- `backward()` 之后图默认被释放；
- 因此可以在模型中使用普通 Python 控制流（`if`、`for`、递归、变长输入）。

这也是 PyTorch 调试友好的重要原因：出错时可以逐行检查中间张量。

## 8. 其他获取梯度的方式

### 8.1 `torch.autograd.grad`

直接返回梯度，不累加到 `.grad`：

```python
grad_w, grad_b = torch.autograd.grad(loss, [w, b])
```

适合需要多次求导、或不想污染 `.grad` 的场景。

### 8.2 自定义 `Function`（进阶）

需要实现不可微操作的自定义反向逻辑时，可以继承 `torch.autograd.Function`，实现 `forward` 和 `backward`。初学阶段了解即可。

## 9. 梯度相关属性速查

| 属性 / 方法 | 含义 |
| --- | --- |
| `requires_grad` | 是否需要跟踪梯度 |
| `requires_grad_(True/False)` | 原地修改该标志 |
| `grad_fn` | 创建该张量的反向函数 |
| `is_leaf` | 是否为叶子张量 |
| `.grad` | 累积的梯度 |
| `.retain_grad()` | 让非叶子张量也保留梯度 |
| `.detach()` | 返回脱离计算图的张量 |
| `torch.no_grad()` | 上下文管理器，关闭梯度记录 |
| `torch.inference_mode()` | 更快的推理模式 |
| `torch.autograd.grad` | 直接求梯度 |
| `Tensor.zero_()` | 把梯度清零 |

## 常见坑

1. **忘记 `zero_grad()`**：梯度跨批次累积，参数更新方向错误。
2. **对同一张图重复 `backward()`**：默认图已释放，会报 “Trying to backward through the graph a second time”；需要时传 `retain_graph=True`。
3. **以为所有张量都有 `.grad`**：默认只有 `requires_grad=True` 的叶子张量有；非叶子需 `retain_grad()`。
4. **对整数张量设 `requires_grad=True`**：只有浮点张量支持梯度。
5. **用 `.item()` 后还想反向**：`.item()` 返回 Python 数值，已脱离计算图；日志记录可以，反向传播不行。
6. **训练时误用 `no_grad()`**：参数不会得到梯度，模型不更新。
7. **原地修改参与梯度的张量**：可能破坏反向所需的历史，尽量使用非原地运算。
8. **用 `.data` 修改参数**：会绕过 autograd 的安全检查，推荐 `detach()`。

## 本章小结

- `requires_grad=True` 让 autograd 跟踪张量上的运算。
- 前向构建动态 DAG，`backward()` 沿图反向求梯度，结果累加到叶子张量的 `.grad`。
- 梯度会累积，训练循环必须清零。
- 推理用 `no_grad()` / `inference_mode()`，冻结参数用 `requires_grad_(False)`。
- `detach()` 切断梯度但共享数据。

## 练习

1. 构造 `w`、`b` 和线性模型，打印 `z.grad_fn`、`loss.grad_fn`，确认哪些是叶子。
2. 不加 `retain_graph` 连续调用两次 `backward()`，观察报错信息。
3. 对一个预训练模型冻结前几层，只训练最后一层，并验证冻结层没有梯度。
