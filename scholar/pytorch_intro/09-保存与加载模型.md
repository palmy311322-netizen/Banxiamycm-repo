# 保存与加载模型

> 本章目标：掌握 `state_dict` 的保存 / 加载方式，能够保存完整检查点以恢复训练，理解跨设备加载与 `weights_only` 的安全意义。

官方教程：[Save and Load the Model](https://pytorch.org/tutorials/beginner/basics/saveloadrun_tutorial.html) · [Saving and Loading Models](https://pytorch.org/tutorials/beginner/saving_loading_models.html) · [torch.save](https://pytorch.org/docs/stable/generated/torch.save.html) · [torch.load](https://pytorch.org/docs/stable/generated/torch.load.html)

## 1. `state_dict` 是什么

`state_dict` 是一个 Python 字典，把每一层的名称映射到它的张量：

```python
for name, tensor in model.state_dict().items():
    print(name, tuple(tensor.shape))
```

对于示例模型，可能包含：

```text
linear_relu_stack.0.weight  (512, 784)
linear_relu_stack.0.bias    (512,)
linear_relu_stack.2.weight  (512, 512)
linear_relu_stack.2.bias    (512,)
linear_relu_stack.4.weight  (10, 512)
linear_relu_stack.4.bias    (10,)
```

注意：

- 只有**有参数的层**（Linear、Conv2d 等）和**注册的缓冲区**（如 BatchNorm 的 `running_mean`、`running_var`）会出现在 `state_dict` 中；
- 它**不包含网络结构**，只包含数值；
- 优化器也有自己的 `state_dict()`，包含动量、二阶矩等状态和超参数。

## 2. 保存 / 加载模型权重（推荐）

### 2.1 保存

```python
torch.save(model.state_dict(), "model_weights.pth")
```

### 2.2 加载

```python
# 1. 先创建结构完全相同的模型
model = NeuralNetwork()

# 2. 读取参数字典并加载
model.load_state_dict(torch.load("model_weights.pth", weights_only=True))

# 3. 推理前切换到评估模式
model.eval()
```

关键点：

- `load_state_dict` 接收的是**字典**，不是文件路径；
- 必须先有模型结构，才能加载参数；
- `weights_only=True` 限制反序列化时只能恢复张量和基本类型，是加载权重的推荐做法。

> 从 PyTorch 2.6 起，`torch.load` 在未显式指定 `weights_only` 时按 `True` 处理（函数签名中的默认值显示为 `None`，但实际行为是安全模式）。旧代码若依赖加载任意 Python 对象，可能需要显式传 `False`，但只应对可信文件这样做。

## 3. 保存 / 加载整个模型

```python
# 保存整个模型对象
torch.save(model, "model.pth")

# 加载（需要类定义可用）
model = torch.load("model.pth", weights_only=False)
model.eval()
```

这种方式代码最少，但问题也最明显：

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| 只保存 `state_dict` | 轻量、灵活、可移植 | 需要重新定义模型结构 |
| 保存整个模型 | 一行保存、一行加载 | 依赖类定义和目录结构；重构后容易失效；pickle 安全风险 |

**官方推荐保存 `state_dict`**。整个模型序列化依赖 Python pickle，它保存的是“类所在的路径”，不是类本身；换项目、改目录或重命名类后就可能加载失败。

## 4. 保存通用检查点（恢复训练）

只保存权重不足以从中断处继续训练。还需要：

- 优化器状态（动量、Adam 的二阶矩等）；
- 当前 epoch；
- 最近的损失；
- 学习率调度器状态等。

### 4.1 保存

```python
torch.save({
    "epoch": epoch,
    "model_state_dict": model.state_dict(),
    "optimizer_state_dict": optimizer.state_dict(),
    "loss": loss,
}, "checkpoint.tar")
```

### 4.2 加载

```python
model = NeuralNetwork()
optimizer = torch.optim.SGD(model.parameters(), lr=1e-3)

checkpoint = torch.load("checkpoint.tar", weights_only=True)

model.load_state_dict(checkpoint["model_state_dict"])
optimizer.load_state_dict(checkpoint["optimizer_state_dict"])

start_epoch = checkpoint["epoch"] + 1
last_loss = checkpoint["loss"]

model.train()          # 继续训练
# 或推理：model.eval()
```

> 检查点通常比纯权重文件大 2～3 倍，因为包含优化器状态。文件扩展名常用 `.tar`。

## 5. 跨设备加载

### 5.1 GPU 保存，CPU 加载

```python
model.load_state_dict(
    torch.load("model_weights.pth", map_location="cpu", weights_only=True)
)
```

### 5.2 CPU 保存，GPU 加载

```python
model.load_state_dict(
    torch.load("model_weights.pth", map_location=device, weights_only=True)
)
model.to(device)
```

`map_location` 会在加载时把存储重新映射到目标设备，避免“保存时在 GPU、加载时没有 GPU”导致的错误。

### 5.3 加载后检查设备与 dtype

```python
next(model.parameters()).device
next(model.parameters()).dtype
```

如果数据类型不一致，可以在加载前转换，或加载后 `model.to(dtype)`。

## 6. 部分加载与迁移学习

当模型结构不完全一致时：

```python
model.load_state_dict(state_dict, strict=False)
```

`strict=False` 会忽略缺失或多余的键。可以检查具体差异：

```python
result = model.load_state_dict(state_dict, strict=False)
print(result.missing_keys)      # 模型中存在但字典中没有
print(result.unexpected_keys)   # 字典中存在但模型中没有
```

常见场景：

- 迁移学习：加载预训练主干，忽略分类头；
- 修改了网络最后几层；
- 从 `DataParallel` 保存的权重通常带有 `module.` 前缀（部分分布式封装也可能出现类似前缀），需要重命名键。

```python
# 去掉 DataParallel 的 "module." 前缀
state_dict = {
    (k[len("module."):] if k.startswith("module.") else k): v
    for k, v in state_dict.items()
}
model.load_state_dict(state_dict)
```

## 7. 安全注意事项

`torch.load` 默认使用 pickle 反序列化，而 pickle **可以执行任意代码**。因此：

1. **不要加载来源不可信的文件**；
2. 加载权重时使用 `weights_only=True`；
3. 对于完全不可信的数据，优先使用更安全的格式（如 `safetensors`），或在隔离环境中检查；
4. 只有在你完全信任文件、且确实需要加载自定义对象时，才使用 `weights_only=False`。

## 8. 导出与部署（进阶）

`state_dict` 适合在同一套 PyTorch 代码中恢复模型。若需要跨框架 / 跨语言部署，可以考虑：

| 方式 | API | 特点 |
| --- | --- | --- |
| `torch.export` | `torch.export.export` + `torch.export.save/load` | 导出静态计算图，`.pt2` 格式 |
| TorchScript | `torch.jit.script` / `torch.jit.trace` | 传统部署格式 |
| ONNX | `torch.onnx.export` | 跨框架推理 |

`torch.export` 示例（来自官方文档思路）：

```python
sample_input = torch.randn(5)
exported_program = torch.export.export(model, (sample_input,))
torch.export.save(exported_program, "model.pt2")

loaded = torch.export.load("model.pt2")
```

初学阶段先把 `state_dict` 用熟即可。

## 9. API 速查

| 用途 | API |
| --- | --- |
| 参数字典 | `model.state_dict()` |
| 加载参数 | `model.load_state_dict(dict, strict=True)` |
| 优化器状态 | `optimizer.state_dict()` / `load_state_dict()` |
| 保存 | `torch.save(obj, path)` |
| 加载 | `torch.load(path, map_location=..., weights_only=True)` |
| 设备映射 | `map_location="cpu"` / `map_location=device` |
| 部分加载 | `strict=False` |
| 导出 | `torch.export.export` / `torch.export.save` |

## 常见坑

1. **`model.load_state_dict("model.pth")`**：参数应该是字典，不是路径；先 `torch.load`。
2. **模型结构不一致**：键名或形状不匹配会报错；用 `strict=False` 并检查 `missing_keys` / `unexpected_keys`。
3. **推理前忘记 `model.eval()`**：Dropout / BatchNorm 行为错误，结果不一致。
4. **GPU 权重在 CPU 上加载**：没有 `map_location` 会报错。
5. **只保存模型权重就恢复训练**：优化器状态丢失，训练动态（如 Adam 矩估计）无法完全恢复。
6. **用 `best_state = model.state_dict()` 记录最佳模型**：这是引用，会随后续训练变化；应 `deepcopy` 或立即 `torch.save`。
7. **加载不可信文件**：pickle 可执行任意代码；坚持 `weights_only=True`。
8. **保存整个模型后重构代码**：类路径变化会导致加载失败。
9. **保存 / 加载后设备或 dtype 不一致**：检查参数所在设备与类型，必要时 `.to(...)`。

## 本章小结

- 保存 `state_dict` 是官方推荐做法：轻量、灵活、可移植。
- 加载权重 = 创建同结构模型 + `load_state_dict(torch.load(..., weights_only=True))`。
- 恢复训练要保存模型、优化器、epoch 等，组成检查点字典。
- 跨设备加载用 `map_location`。
- 推理前必须 `model.eval()`。
- pickle 有安全风险，不可信文件不要用 `weights_only=False`。

## 练习

1. 训练一个 FashionMNIST 模型，分别用“只保存权重”和“保存整个模型”两种方式保存并加载，比较文件大小与可移植性。
2. 保存一个包含 `epoch`、模型、优化器状态的检查点，模拟中断后从第 3 个 epoch 继续训练。
3. 在 GPU（或 CPU）上保存权重，然后用 `map_location` 加载到另一个设备，验证参数位置。
4. 构造一个少一层的模型，用 `strict=False` 加载原权重，打印 `missing_keys` 和 `unexpected_keys`。
